## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline Badge padding |
| sm | 8px | Compact element spacing, table cell padding |
| md | 16px | Default element spacing, filter bar gaps |
| lg | 24px | Section padding, card internal padding |
| xl | 32px | Layout gaps between major sections |
| 2xl | 48px | Empty-state vertical padding |
| 3xl | 64px | Page-level top padding |

Exceptions:
- Touch targets for action buttons (Revogar): `min-height: 44px` on mobile — applied exclusively as `min-height`, not as padding or gap value. Sourced from WCAG 2.5.5.
- Admin layout main content: `lg:p-6 p-4` (24px desktop / 16px mobile) — existing pattern from `(admin)/layout.tsx`.
- Empty-state card: `p-12` (48px all sides) — existing pattern from `PedidosCrud.tsx`.

Source: Existing `PedidosCrud.tsx` + admin layout.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 14px (text-sm) | 400 (regular) | 1.5 |
| Label | 12px (text-xs) | 400 (regular) | 1.4 |
| Heading | 20px (text-xl) | 600 (semibold) | 1.2 |
| Display | 16px (text-base) | 600 (semibold) | 1.2 |

Notes:
- Exactly 2 weights in use: `400` (regular) and `600` (semibold). Display and Heading are differentiated by size (16px vs 20px), not weight.
- Table header cells use `text-xs` (12px weight 400) — existing pattern from `PedidosCrud.tsx` `TableHead className="text-xs"`.
- Page-level headings use `text-xl font-semibold text-white` — existing pattern `h1 className="text-xl font-semibold text-white"`.
- Body copy (empty states, descriptions) uses `text-sm text-white/60`.
- Countdown badge values use `text-xs` for compact display inside table cells. Size distinction alone (text-xs) provides sufficient visual hierarchy without a third weight.
- Press Start 2P is NOT used in admin panel — it is reserved for public-facing hero and section headings only. Admin uses Sora throughout.

Source: `PedidosCrud.tsx` observed patterns + `globals.css`.

## Interaction Contracts

### /admin/beneficios — BeneficiosCrud

**Table columns (D-13):**
1. Player (Minecraft username)
2. Benefício (rank/item name)
3. Data de compra (formatted PT-BR date)
4. Valor pago (R$ formatted, e.g. "R$ 49,90")
5. Expira em — CountdownBadge component (green/yellow/red per D-14)
6. Status do servidor — DeliveryStatusBadge (Entregue / Pendente)
7. Actions — DropdownMenu with "Revogar Benefício" item (only if status != expired/revoked)

**DropdownMenu trigger accessibility:**
- The `DropdownMenuTrigger` wrapping `MoreHorizontal` must include `aria-label="Ações do benefício"` so screen readers announce the button purpose. Example: `<DropdownMenuTrigger asChild><Button variant="ghost" size="icon" aria-label="Ações do benefício"><MoreHorizontal className="h-4 w-4" /></Button></DropdownMenuTrigger>`

**Filters (D-15):**
- Input: text search by player name (debounced 300ms, client-side or URL param)
- Select: tipo de benefício (All + each unique rank name)
- Select: status (Todos / Ativo / Expirando / Expirado)

**CountdownBadge behavior:**
- Props: `expiresAt: Date | null`
- If null or status is expired/revoked: render "Expirado" badge (muted)
- If > 14 days: green Badge — `text-brand-online border-brand-online/30 bg-brand-online/10`
- If 7–14 days: yellow Badge — `text-brand-yellow border-brand-yellow/30 bg-brand-yellow/10` + AlertTriangle icon
- If < 7 days: red Badge — `text-brand-accent border-brand-accent/30 bg-brand-accent/10` + AlertTriangle icon
- Copy: "{N} dias restantes" (computed from now to expiresAt)
- Typography: `text-xs` (weight 400, inherited from body)

**Revogar flow:**
1. Admin clicks DropdownMenuItem "Revogar Benefício"
2. AlertDialog opens (D-16 confirmed)
3. Admin clicks "Sim, revogar"
4. Button enters loading state (disabled + spinner)
5. Server Action `revogarBeneficio(orderId)` called
6. On success: toast.success("Benefício revogado com sucesso.") + router.refresh()
7. On error: toast.error("Erro ao revogar. Tente novamente.")

**Skeleton / loading state (Claude's Discretion):**
- Page uses Suspense boundary with skeleton: 5 rows × 7 columns, each cell a `<Skeleton className="h-4 w-full" />` block.
- Skeleton wrapper: `bg-brand-card rounded-card overflow-hidden`.

**Pagination:**
- Identical to PedidosCrud: pageSize 20, prev/next buttons, "Página X de Y" label.

### /admin/vendas — VendasCrud

**Table columns (D-18):**
1. # (order ID, right-aligned, text-muted)
2. Player (Minecraft username)
3. Item (product name)
4. Valor (R$ formatted)
5. Status do pagamento — StatusBadge (pending/paid/failed)
6. Método de pagamento (e.g. "Pix")
7. ID MercadoPago (truncated to 12 chars + ellipsis, full value in title tooltip)
8. Status de entrega — DeliveryStatusBadge
9. Data (PT-BR date, short format)

**Filters (D-19):**
- Select: status do pedido (Todos / Pendente / Pago / Falhou / Entregue)
- Date range: two `<Input type="date">` fields (De / Até) — URL params `dateFrom` and `dateTo`

**Read-only table:** No row actions. No destructive confirmations.

**Pagination:** pageSize 20, same pattern as BeneficiosCrud.

**Export CSV:** NOT implemented in this phase (D-20 deferred).
